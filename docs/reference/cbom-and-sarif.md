# CBOM and SARIF Data Formats

This document specifies the CycloneDX 1.6 Cryptographic Bill of Materials (CBOM) and OASIS SARIF 2.1.0 schemas generated by PQCanary.

---

## 1. CycloneDX 1.6 Cryptographic Bill of Materials (CBOM)

CycloneDX 1.6 introduced standard representations for cryptographic algorithms, keys, protocols, and certificates as first-class software bill of materials (BOM) components.

Generating a CBOM:
```bash
pqcanary cbom ./my-project --output cbom.json
```

### NIST Quantum Security Level Mapping
- **Level 0**: Quantum-vulnerable (RSA, ECDSA, ECDH, DSA, classic DH).
- **Level 1**: Equivalent to AES-128 key exhaustion (ML-KEM-512).
- **Level 2**: Equivalent to SHA-256 collision search (ML-DSA-44).
- **Level 3**: Equivalent to AES-192 key exhaustion (ML-KEM-768, ML-DSA-65).
- **Level 5**: Equivalent to AES-256 key exhaustion (ML-KEM-1024, ML-DSA-87, SLH-DSA-256).

## 2. OASIS SARIF 2.1.0 (Static Analysis Results Interchange Format)

OASIS SARIF 2.1.0 is the industry standard for publishing static analysis results to platforms such as GitHub Advanced Security Code Scanning, Azure DevOps, and GitLab SAST.

Generating a SARIF report:
```bash
pqcanary sarif ./my-project --output pqcanary.sarif
```

### GitHub Code Scanning Mapping
- SARIF `level: "error"` maps to GitHub **Critical/High alert**.
- SARIF `level: "warning"` maps to GitHub **Medium alert**.
- SARIF `level: "note"` maps to GitHub **Low/Info alert**.
- `security-severity` scores (0.0 to 10.0) populate the CVSS severity badge in the GitHub Security tab.

## 3. CBOM Semantic Drift & Quantum Downgrade Detection

PQCanary includes a native CBOM comparison engine (`CbomDiffEngine`) that evaluates two consecutive CycloneDX 1.6 releases to detect architectural drift and quality regressions:

```bash
# Compare baseline against current CBOM
pqcanary diff baseline-cbom.json current-cbom.json --fail-on-downgrade
```

### Semantic Drift Metrics

| Metric | Field | Description |
| :--- | :--- | :--- |
| **New Assets** | `added_assets` | Newly introduced cryptographic components and algorithms. |
| **Retired Assets** | `removed_assets` | Components removed from the active software bill of materials. |
| **Algorithmic Changes** | `algorithm_changes` | In-place modifications to primitives, curves, or parameter sizes. |
| **Quantum Downgrade Regressions** | `quantum_downgrade_regressions` | **Critical CI/CD Quality Gate**: Triggers when an asset was migrated to PQC (e.g. ML-KEM-768) but rolled back to a classical algorithm (e.g. RSA-2048). |
